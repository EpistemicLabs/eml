## EML v0.23.0-alpha.1 (Experimental)

The task state model: who works on a task, who it waits on and when it runs next now live in the brain, so every member of a shared space sees the same thing. Early builds: things may break. Offered only to cockpits on the Alpha (experimental) update channel.

**Brain schema 23.** The first start migrates every brain to schema 23, with a backup first. A cockpit on schema 22 stops syncing a shared space once a member writes from 23: every member of a shared space moves to this build. Going back to v0.22 needs the backup from before the update. After the update, the task migration of each space runs from a dry run its owner has seen.

### What's new

- **Runs:** every session on a task leaves a run in the brain — running, idle or ended, with its last result line — so the board shows who works on a task on every member's cockpit. A run silent for over an hour shows as Stale.
- **Hand-over that starts once:** Delegate now records a request and the runner starts the task from it; a task's status only moves forward. Work on it now hands nothing to the agent on its own.
- **Waits and parking:** a task holds one wait per session that asked; questions come before reviews. Park a wait until tomorrow, Monday or with no date: the task shows as Parked for everyone and comes back by itself.
- **Schedules in the brain:** a scheduled agent's timing sits on the task — once, until the goal is reached, or repeating, each run in the same session or a new one. The board groups them as Missions, Routines and Starts later.
- **Task panel:** the goal under the title, one short Waiting on line with Park…, the schedule with Change schedule…, actions that fit the task's state, and the sessions on the task by what needs you — earlier sessions included.
- **Task migration:** a dry run lists every change per space before anything is written: delegations without a checkpoint get one and stay unstarted, blockers become waits, intents join the goal.
