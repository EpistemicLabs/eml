## EML v0.21.5

The brain now flags a second write under an existing title when their content overlaps, and a new hygiene check goes through the brain for pairs that say the same thing. No schema change and no migration.

### What's new

- **Duplicates under one title:** when a write has the title of an existing engram, overlapping content and no link to it, the agent is told and either links the two or records why they are distinct.
- **Conflict scan in brain hygiene:** a new check finds pairs of existing engrams that look like the same topic; a pair you judged once is not shown again.
- **Update check for shared spaces:** an update that changes the brain format waits until every shared space on this computer has caught up with its relay.

### Conflict detection

- **Same title, no link.** The write-time conflict check left out candidates with the title of the new write. Two sessions writing the same decision under one title minutes apart went unflagged. Such a candidate is now reported, marked "same title — check the lineage link". A series under one title stays quiet once each member links to the one before it.
- **A judged pair stays judged.** Two engrams that already have a relation between them are no longer reported, whatever the relation. Engrams bound to the same task are one thread and are not reported either, except a pair with the same title.
- **Recording "these are distinct".** `eml_relate` with `distinct_from` and a reason records that a pair was compared and is not a conflict. The brain stores it as a `related_to` relation with a fixed marker in its explanation and metadata, so the pair is not reported again.
- **Hygiene check `conflict-scan`.** The same filter over the existing active engrams: one finding per open pair, on the newer engram, at most 20 per run. It is a recurring review check and arrives through the brain hygiene banner like the others. On a brain that was never scanned the first run is the largest; after that, the remaining and the new pairs show.

### Op log

- **A brain format change keeps the log replayable.** When a later release changes the brain format, the migration writes the migrated state into the log as a checkpoint with a snapshot, and a rebuild or verify starts from there. This release prepares it; nothing changes for a brain on the current format.
- **Shared spaces.** The cockpit refuses an update that changes the brain format while a shared space on this computer is offline, catching up, waiting for its key or joining. The message names the space. Updates within one brain format, like this one, are not held back.
- **Replay is tested against a frozen log.** CI replays a stored log of the current brain format on Linux, macOS and Windows; each must reach the same state.

### Development

- **Two fixed dev cockpits.** `cockpit/scripts/dev-home.sh` serves two dev cockpits (ports 4318 and 4319) from any worktree, so two members of one shared space can be checked locally, with snapshot and reset of the local brains. `dev-refresh-brain.sh` and `seed-sample-brain.sh` are fitted to it.
