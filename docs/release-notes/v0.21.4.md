## EML v0.21.4

Three new cockpit plugins (Repository, Shell, Time), Qwen Code as a third agent for open and own models (beta, macOS), and a "What's new" view after every update. No schema change and no migration.

### What's new

- **Repository plugin:** read a project's code next to the session — its changes, files and commits, read-only.
- **Shell plugin:** a terminal on this computer in a pane, your own login shell.
- **Time plugin:** your work time and your agents' time per project, counted without start or stop.
- **Brain can be switched off** as a pane view; the agents' brain stays.
- **Qwen Code (beta, macOS):** sessions with open and own models over any OpenAI-compatible endpoint — OpenRouter, a vendor's API, or Ollama and vLLM.
- **What's new after an update:** this view, with the highlights of every release the update brought.
- **Mouse in reattached panes:** scrolling and selection keep working after a reload or a second pane.

### Cockpit plugins

- **Repository.** One checkout of a project — the project folder or one of its git worktrees — in three tabs. Changes: uncommitted changes (untracked files included) and what the branch committed since the default branch, as diffs with syntax colours and line numbers. Files: the whole tree with "Go to file…" and an "ignored" toggle; a file opens read-only with line numbers, folding and search. Commits: the branch's commits since the default branch (or the latest 50 on it), each with its diff. Worktrees gets an icon per row that opens the checkout here. Files that look like secrets (`.env*` except examples, key files, `.npmrc`, `.netrc` …) show only after an explicit reveal; git runs without external diff or textconv programs, and paths outside the checkout are refused.
- **Shell.** Your login shell in your home folder, as your terminal app opens it, not tied to a project. Same terminal as agent sessions: a reload reattaches, full-screen programs work; closing the pane ends the shell, and after `exit` Enter starts a new one. It gets none of the cockpit's variables and does not count as an agent session. It opens only on this computer; a remote viewer (Tailscale) gets it only after `eml-cockpit remote shell on`.
- **Time.** Two clocks per project, session and task, per day. Yours runs while a cockpit tab is visible and had input in the last 5 minutes (a hidden tab keeps counting for 2 minutes); your agents' runs while a session's turn works, in its own column. Today or the last 7 days, grouped by space, expandable to tasks and sessions. Stored as ids and seconds under the cockpit home; nothing is counted while the plugin is off.
- **Brain is a plugin too.** Settings › EML Plugins switches the Brain pane view off; the header's Brain tab and the agents' brain stay. A pane on a plugin that is switched off moves to the first one still on.
- **Defaults.** Brain, Note and Worktrees stay on as before; Repository, Shell and Time start off — switch them on in Settings › EML Plugins. A switch you set is kept.

### Qwen Code (beta, macOS)

A third agent CLI next to Claude Code and Codex, for open and own models behind an OpenAI-compatible endpoint.

- **Set up** in Settings › Models › Qwen Code: "Set up now" installs the cockpit's own Qwen Code from npm (checked against the registry's checksum, and only a version that has been out for two days). Then base URL, model and an optional API key; the key is kept in its own owner-only file and never shown again.
- **Permissions:** auto (sandbox, Qwen Code's classifier allows safe actions), ask (sandbox, every edit and command comes to you) or off (no sandbox). Workers always run in auto.
- **Brain:** boot, project block, reminders and brain reads and writes as in the other agents; writes are stamped with the session, the model and `qwen-cli`. The context-size check before a compaction works for Qwen sessions too. `--provider qwen` starts a worker with it.
- **Known limits:**
  - The API key reaches the session in its environment, so commands the model runs can read it. Use a key with a spending limit; a local endpoint needs none.
  - The sandbox keeps writes in the project and the cockpit's folders, but a session can still write Qwen Code's own settings, extensions and skills and the project's `.qwen` folder. A session steered by a prompt injection could leave a hook or MCP server there that later Qwen sessions run — an unsandboxed one in off mode too. A fix is planned.
  - One endpoint and model for all Qwen sessions; a fresh cockpit still asks for a Claude Code sign-in during onboarding.

### After an update

- **What's new.** After an update from the banner the cockpit opens a dialog: the new version, a brain migration if it had one, and the "What's new" of every release since the version you came from, newest first. "Got it" closes it for good. Rollbacks and migrations without an app update keep the banner as before.
- **Release notes** now always start with a "What's new" section; the release checks it.

### Terminal

- **Mouse in reattached panes.** After a reload or a second pane on the same session, a program that reads the mouse in SGR mode (Qwen Code, many full-screen tools) got reports it could not read: no wheel scrolling, no selection. The replay now restores the encoding.
- **A resize while a terminal opens is no longer lost.** A pane that resized while its session was still starting kept the old size, and output broke over the pane edge.
