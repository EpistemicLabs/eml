## EML v0.21.1

Brain hygiene can finish what v0.21 left for it. No schema change and no migration.

### What changed for agents

- **Learnings outside the agent scope** (check `learning-outside-agent-scope`). Until now the check told the agent to move such a learning with `eml_update(scope)`. In the cockpit that call is refused, because the learning sits in the space and `agent.<id>` lives in the agent's brain. The check now has the agent decide per entry. A lesson about how the agent works is written anew with `eml_learning` in `agent.<id>`, and the old one is invalidated; its evidence stays on the old one. Knowledge about the work becomes a note in its project, replacing the learning. When the agent is unsure, it asks.
- **Rules in global or a user scope** (`rule-in-global-scope`, `rule-in-user-scope`) are written anew with `eml_rule` in `agent.<id>`, and the old one is invalidated. Content, why, trigger and agreement are carried over. A rule that governs a project is still moved to `project.<id>` with `eml_update(scope)`.
- **Profiles in the wrong scope** (`profile-scope`). One that belongs to a person or the agent (`user.<id>`, `agent.<id>`) is written anew with `eml_profile`, and the old one is invalidated. One that belongs to an entity still replaces the old one with `supersedes`.

Fixes #179.
